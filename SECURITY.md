# Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in public GitHub Issues.

Use the repository's private security reporting/contact mechanism when available. Include a clear description, affected version, reproduction steps, and impact. Do not include passwords, tokens, private account data, or other secrets.

## Supported releases

The latest public release is the primary supported release line. Security fixes may be provided for older releases when practical.

## Release hygiene

Never commit signing keys, keystore passwords, Firebase credentials, API secrets, or private configuration files.
